# 商业工作流与验收

## 三种入口

| 用户任务 | 实际工作与交付 | 完成条件 |
| --- | --- | --- |
| 定向分析 directed | 从本地素材/报告回答具体问题：开头承诺、购买理由、证明、商品识别、信任与行动入口；记录时间点和修改建议 | 每个结论能追溯实际文件/来源，未知明确；需要生产时形成对应分镜 |
| 策略探索 explore | 对同一商品和目标比较不同人群情境或卖点角度；说明依据、适用条件、成本与假设，推荐优先方案 | 不同角度确实改变购买理由或证明方式，主方案及替代方案有 rationale/evidence |
| 灵感激发 inspire | 从参考中抽取机制，提出原创钩子、场景或演示方式；保持商品事实，允许迭代碰撞 | 原创方向可落实为镜头，不照搬品牌内容，不编造爆款指标 |

只分析时停在分析，不触发生成。只做接口试跑时可用 version-1，清楚标为技术验收。商业生产使用 version-2，把主方案落实成片；代码验证结构和绑定，Agent 阅读证据、判断内容并复核事实。

## 商品与证据

先整理最少必要资料：商品是什么、当前目标、平台、已有实物或概念参考。人群/脚本可先给带理由的建议；真实商品关键配料、功效、价格和授权缺失时不代填。用户明确允许虚构时，建立独立 concept 来源，所有商品设定标 fictional，交付中显示披露。

来源登记记录标题、实际定位地址、日期、摘要、范围与用途。web 类以 HTTPS URL 定位；local/vendor 类保留项目内原报告并记录 SHA256。实际打开和阅读来源后再判断能支持什么。商品证据 scope=product，品类=category，参考=reference，虚构设计=concept；只有 product 证据支持真实 SKU verified 声明。

使用供应商报告时保留正文，不把不提供的字段变成“零”。蝉镜简报不等于千川逐素材投放库，有米云和 Clipcat 的能力以当前授权接口/实际返回为准。公开资料可以补创意思路，不能替代原始 GMV、广告消耗和投放归因。已有数据、API 获取、离线缓存和商用授权分别记录。

## 策略与分镜

使用一个明确的购买任务组织：谁在什么情境下，想解决什么选择问题，为什么看这个商品，凭什么相信，下一步怎么做。提出推荐及假设，避免只拍产品的空泛美图。hook→proof→CTA 是本格式的执行结构；长片可以插入 context。每个镜头有目的、所用声明、可观察验收项和完整提示词。

建立外观锁：形状、颜色、包装、文字、关键细节、应避免的变形。优先复用同一真实 SKU 的授权参考图或实物视频；虚构图注明 concept。真实商品没有对应参考时保留草稿，或经用户同意设置 visual_mode=concept 并显示 disclosure 后交付概念画面。逐镜头 assets 可覆盖公共参考，首尾帧与 reference 模式按供应商限制选择。文本外观锁不是视觉保证，成片仍须对照。

声音选择 generated/external/none；字幕选择 post/generated/none。默认建议 post 字幕，避免依赖视频模型准确生成汉字。外部声音由用户提供已授权本地文件，工具不暗中采购音乐或克隆音色。生成式口播必须听音核对，存在音轨不代表口播正确。

## 执行与费用

`storyboard-check` → `storyboard-export` → 逐个 `prepare` → 展示整组次数/完整提示/引用素材/估算与总预算 → 获准后逐项 `execute`。v2 导出必须保存真源路径，准备时把分镜和本地证据文件纳入指纹；修改来源、提示、参考图或配置后重新准备。

旧商品或已用完的一次性预算不覆盖新案例。每次执行前核对该轮累计支出/已提交数，包括未知结果的提交；结果未知先核对旧任务。程序没有供应商账单硬上限，估算不保证实际收费。剩余预算不足、价格未知未获准或次数用完时停止，不自动付费重试或换服务。

## 本地拆解、制作与恢复

Python 项目中安装 `commerce-creative-skill[media]` 可选组件，或从源码 `python -m pip install '.[media]'`。只装在该项目解释器中，无需改系统。包含 PyAV、Pillow 和 imageio-ffmpeg；运行不会自动下载组件。缺少时明确报告安装方法。

`media-inspect` 支持最长10分钟的本地 MP4/MOV、WebM/MKV、AVI；长片先分段。全程解码视频，单独核对实际画面起止/缺口、旋转矩阵和显示像素比例，按时间采样最多120帧，另导出音轨。Agent 读取画面并听音/核对已授权文字稿，记录时间码、原话和不确定处；工具没有假装内置完整视频理解模型或自动识别口味。录入已有字幕/转写也要核对原片。

`render` 把镜头按批准时间线裁剪，等比缩放补边、统一24帧并拼接；不裁商品去凑比例、不无声冻结短片。支持本地外部配音与音乐，音乐混音音量默认为0.12；字幕和虚构披露烧录进视频。保留原文件、输入输出指纹和变换报告。检查中文字体、音量、安全区及剪辑衔接；输出尺寸不是模型原生尺寸。不同编码仍可通过标准化拼接；旧 `compose` 保留无损且同编码的用途。

TUN fake-DNS 导致下载失败时，可显式 `download --public-dns`：只把产物主机名交给固定 HTTPS 解析器，验证公网 IP 后固定连接并校验 TLS 原主机名。此操作不改系统 DNS/代理、不向存储转发模型密钥，也不跟随重定向。普通内网地址仍拒绝。

## 内容验收

先运行 `media-inspect`，再运行 `review-template`。审阅者观看完整最终文件并听音后，填 reviewer、full_video_watched、audio_listened、shots_reviewed，逐项给 PASS/FAIL/UNKNOWN、具体 shot、seconds、note。仅看分镜或采样图时保留 UNKNOWN。自动化可检查规格、指纹和审阅完整性；观察判断由具备实际视听能力的 Agent/人完成，不能把勾选当独立事实认证。

检查：钩子、证明、购买理由、商品一致性、声明、文字、声音、连续性、CTA，以及虚构披露。`acceptance-check` 仅在规格及必需审阅均通过时返回内容通过；另列真实商品还原和销售效果。失败结果给出 revision_shots，保留其余已完成镜头；新版本记录 revision/parent_digest 与修改理由，重新验收相关内容。没有生成时可以交付分析与可执行草稿，不能补造视频通过。

## 结果与项目接续

把来源、主方案/替代、分镜、请求、任务 ID、用量估算/实际、原片/派生文件、审阅记录和未解决项保存在当前项目。继续工作先读取这些真源，不借其他项目历史。用户改变判断时修改对应资料并保留旧版。平台发布、定时与云素材库另走原有授权流程；本地内容通过不会自动发到平台。
